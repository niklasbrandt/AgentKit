# Init: make a repository a dark factory

Run inside the target repository. Needs `gh` ( with the `project` scope: `gh auth refresh -s project` ), `jq`, `python3`.

## Steps

1. **Find or create the board.** `init.sh` does this itself when no `--project` is given ( `scripts/project.sh create` ): it uses the project already linked to the repository ( several linked: it stops and lists them, pass `--project <n>` ); else the owner's project titled like the repository, which it links; else it creates one named after the repository and links it. Then it gives the **Status** field the seven columns of the language preset through the API ( `en` Epics, Backlog, Ready, In Progress (Human), In Progress (Agent), In Review, Done; `de` Epics, Backlog, Bereit, In Arbeit (Mensch), In Arbeit (Agent), Zur Review, Fertig ): an empty board gets exactly these seven, GitHub's defaults ( Todo, In Progress, Done ) are dropped; a board with cards keeps its columns and gets the missing ones only with `project.sh columns <n> <owner> --force`. **Before letting it create one, look at what is there:** `gh project list --owner <owner>` and the repository's linked projects. If the owner already runs a board for this repository ( other column names, more views ), use it and map its columns in `.factory.json` under `columns` instead of adding seven new ones; extend it only where a column of the workflow is really missing. A second board next to an existing one is the wrong answer unless the owner asks for it. It also makes sure there is one Board view named `kanban` ( `.factory.json` key `view` overrides the name ): GitHub's default table "View 1" is renamed and switched, an existing view of that name is switched to Board, otherwise one is created and the owner's other views stay. Manual, no API: the project's **Default repository** setting ( Project settings; only affects issues created from the project's UI ) and the built-in workflows, which `project.sh workflows` lists and warns about when an Auto-add, Item closed or Auto-close one is on.
2. **Ask the owner at once, in one message:** project number ( only if several boards could be meant; otherwise none ); language preset ( `en` or `de` ); the verify command ( what proves a change works: build, tests, typecheck, smoke test; if it drives a headless browser: through one central launcher, muted and windowless, `headless: 'new'`, `--mute-audio`, no focus or window calls, the app's flag that creates no audio context, under `run.sh`; the upper bounds `capacity.sh` works under: `agentsMax` ( default 6 ) and `headlessMax` ( default 4; `headlessCap` is its alias ), the owner's dev-server ports `ownerPorts` and the owner-activity thresholds `idleMinutes` ( 10 ) and `afkMinutes` ( 30 ); Headless checks never run the owner's installed browser bundle ( on macOS the app bundle under /Applications ): the operating system then treats every headless instance as 'the browser is running', so the owner's own browser will not start, and focus, keyboard and the audio session are routed to the wrong process. Use a separate browser build ( Chrome for Testing, installed into a cache folder by a repo script ) through the repo's single launcher, with an env override for the path. ); how to run the repo locally ( the line for the ticket's "local:" ); umbrella branches in use; the owner's own dev server port, if any; anything repo-specific to add to the Collaboration section. The owner handle and name default to the repository's owner on GitHub.
3. **Run the script:**

   ```
   ${CLAUDE_PLUGIN_ROOT}/scripts/init.sh [--project <n>] [--lang en|de] [--owner <handle>] [--name "<Full Name>"] \
       --verify "<verify command>" --run "<local run command>" [--umbrella "feat/a, feat/b"] [--dry-run] [--replace-existing]
   ```

   - `--dry-run` prints the rendered sections and writes nothing.
   - The sections are written between `<!-- factory:collaboration:start/end -->` and `<!-- factory:delegation:start/end -->` markers, so running it again updates them in place and leaves the rest of the file alone. A pre-existing `## Collaboration` section without markers is only replaced with `--replace-existing`; repo-specific items of the old section are moved to a `### Repo-specific` subsection and printed ( review them ).
   - It writes `.factory.json` ( project, owner, reviewer, lang, verify list, umbrella; the capacity keys `agentsMax`, `headlessMax`, `diskMBs`, `ownerPorts`, `idleMinutes`, `afkMinutes` only where missing ), adds `STATE.md` ( the orchestrator's state sheet ) to `.gitignore` and creates its skeleton if missing, creates the labels of the preset ( `idea` / `idee`, `feature`, `bug`, `documentation`, `merged` / `gemergt` ), adds the preset's columns where the board is empty ( `project.sh columns` ), and runs `board.sh ids`, which prints the Status field id and option ids and exits 1 if a column is still missing.
4. **Board workflows and default repository:** `init.sh` prints the workflows' state ( `project.sh workflows` ). If it warns, tell the owner to open the project, menu → Workflows, and switch **off** "Auto-add sub-issues to project" ( and any "Auto-add to project" ) ( otherwise every sub-issue of a work package reappears as a card without a column whenever it is edited ) and "Item closed → Done" ( only the owner sets Done ); switching is UI-only. Until then, `board.sh tidy` removes such cards. Also ask the owner to set the project's **Default repository** to the repository ( Project settings ), UI-only as well.
5. **Check:** `CLAUDE.md` must import `AGENTS.md` ( `@AGENTS.md` ) so Claude Code reads the Collaboration section ( Cursor and Antigravity read AGENTS.md directly ). Add repo-specific facts the templates cannot know ( ports, where the plan lives, the deploy command ) outside the markers, under `### Repo-specific`. Read the generated text once.
6. **Commit** on a branch or `main` as the owner prefers: `docs: add dark-factory collaboration rules`. Do not move cards or create tickets as part of init.

## Templates

`templates/<lang>/AGENTS.collaboration.md` and `templates/<lang>/CLAUDE.delegation.md`. Placeholders: `{{OWNER}}` ( handle ), `{{OWNER_NAME}}`, `{{PROJECT}}`, `{{PROJECT_NAME}}`, `{{PROJECT_URL}}`, `{{VERIFY}}`, `{{LOCAL_RUN}}`, `{{UMBRELLA_NOTE}}`, `{{TRANSCRIPT_DIR}}`, `{{PLUGIN_URL}}`. To adapt the rules for one repository only, edit the generated section's text inside that repository and drop the markers ( init then needs `--replace-existing` to touch it again ). To change a rule for every repository, change the template here, bump the plugin version, add the `CHANGELOG.md` entry and its copy in the README, and update the README sections a significant change touches ( upstream first; README "Maintaining AgentKit" ).
